# rx — remote process execution over SSH (agent transport)

Read this whole file once; it is short and complete. It describes capabilities,
not a mandatory workflow — compose the commands as the task needs.

Invariants:
- Every command prints exactly one JSON object on stdout (type field). The only
  exceptions are `start --pipe` (data on stdout, JSON handle on stderr) and the
  raw streaming used internally.
- Command arguments and stdin bytes are transported verbatim over the SSH
  channel — no remote shell parses them. There is nothing to escape/quote.
- Process IDs are 8 lowercase hex characters.
- Trust model: rxd runs as the SSH user and is a transport, not a sandbox or
  privilege boundary. It can do anything that user can (write any path via cp,
  elevate via `doas` in a command). Your SSH access is the whole trust boundary.

## Model

Commands run detached on the remote under a private per-user state dir; stdout
and stderr are captured to files that survive disconnect. Two entry points over
that substrate:
- run   — synchronous. Blocks up to a timeout; if the command outlives it, the
          process keeps running and a `running` handle is returned instead.
- start — returns a handle immediately. For long-lived, streaming, or
          interactive processes you read/write later.
- wait  — block on an already-started process until it exits or a timeout,
          returning the same completed/running shapes as run (no polling).

## Commands

  run   HOST [--cwd DIR] [--env K=V]... [--timeout SECS] [--keep-stdin-open] [--keep] -- CMD...
  start HOST [--cwd DIR] [--env K=V]... [--pipe] [--no-close-stdin] -- CMD...
  wait  HOST ID [--timeout SECS]
  status HOST ID
  stdout HOST ID [--offset N] [--limit N]
  stderr HOST ID [--offset N] [--limit N]
  write HOST ID [TEXT] [--raw]
  close-stdin HOST ID
  kill HOST ID
  list HOST
  clean HOST
  cp    LOCAL HOST:PATH [--mode OCTAL] [--owner USER] [--group GRP]
  deploy HOST
  setup [--version V] [--arch ARCH]... [--force]
  skill
  daemon start|stop|status

Notes:
- Everything after `--` is the remote argv. `--` is optional but disambiguates a
  command whose own flags could collide with rx options; put rx options before
  it. execvp runs the argv directly — no shell, so no globbing/redirection/`;`.
- --cwd and --env set the working directory and environment directly, so you
  don't need a `sh -c 'cd DIR && K=V ...'` wrapper. --env is repeatable and its
  overrides layer on the inherited environment.
- cp writes atomically: the file streams to a temp file, gets its mode/owner/
  group, then is renamed into place — it never appears with default perms.
  --mode always works; --owner/--group need a privileged rxd and error otherwise.
- run: stdin, if piped, is fed to the process, then EOF is sent so readers
  terminate. With no piped stdin, EOF is sent immediately. --keep-stdin-open
  suppresses the EOF. Inline stdin is capped at 4 MiB; larger uses start+pipe.
- run is ephemeral by default: a `completed` response whose output is small
  enough to be seen in full (<=16 KiB/stream) also deletes the remote process dir
  (no leftover state). The dir is KEPT when output is truncated or larger than
  that, or when backgrounded (`running`) — so bigger output stays re-pageable via
  stdout/stderr --offset instead of forcing a re-run. Pass --keep to always
  retain the dir after a completed run.
- write TEXT appends a newline unless --raw. With TEXT omitted and stdin piped,
  the stream is forwarded raw and unbounded (binary-safe). close-stdin sends EOF.
- start --pipe: local stdin → remote stdin and remote stdout → local stdout as
  raw bytes; the JSON handle is written to stderr.

## Text encoding

stdout/stderr/data fields pair with an `encoding`:
- utf8   — the JSON string is the literal output; use it directly.
- base64 — output was not clean UTF-8 (binary or embedded NUL); base64-decode it.

## Response shapes (by type)

  completed {id, exit_code|null, signal|null, exec_error?, duration_ms,
             stdout, stdout_encoding, stderr, stderr_encoding,
             stdout_size, stderr_size, stdout_truncated, stderr_truncated}
  running   {id, reason, stdout_size, stderr_size, hint}
  started   {id}
  status    {id, state, cmd, started, ended|null,
             exit_code|null, signal|null, stdout_size, stderr_size}
  output    {data, encoding, offset, size}
  written   {bytes}          # from close-stdin, bytes:0 means EOF sent
  copied    {path, bytes, mode?}
  killed    {id}
  list      {processes:[{id, state, cmd}]}
  cleaned   {removed:[id...]}
  version   {version, protocol}
  error     {message, code?, retryable?, hint?}

- run and wait yield completed or running. exit_code is null when signal is set.
- exec_error is present only when the command never started (the binary wasn't
  found or wasn't executable) — then exit_code and signal are both null and
  stderr carries a `rx: exec …` line. Values: command_not_found · permission_denied
  · exec_format_error · errno_<n>. Branch on this to tell "the tool isn't there"
  (install it, or use another) from "the tool ran and exited 127".
- After an ephemeral completed run the process id is still in the response for
  logging, but status/stdout/stderr for that id return process_not_found.
- state: running | exited(N) | signaled(N) | exited(killed) | exited(unknown) |
  exec_failed(reason)  (reason as in exec_error above; the status view of a
  command that failed to start).
- completed inlines up to the last 256 KiB per stream; when *_truncated is true
  the full output remains readable via stdout/stderr with --offset.
- output.size is the total file size — pass it back as the next --offset to read
  incrementally; size == offset with an exited state means fully drained.

## Error codes (error.code)

  bad_request · invalid_process_id · process_not_found · process_exited ·
  timeout · not_deployed · unsupported · ssh_unreachable · ssh_auth · internal

Branch on code, not message text. `retryable:true` means the same call may
succeed on retry (e.g. after an auto-deploy, or a transient ssh_unreachable).

## Deploy and connections

rxd is the remote binary; rx deploys the arch-matched build to ~/.local/bin/rxd
(`rx deploy HOST`, needs a local cache from `rx setup`). Set
REM_EXEC_AUTO_DEPLOY=1 to deploy-and-retry automatically against a missing or
outdated remote. rx multiplexes SSH connections, so repeated operations to a
host reuse one connection.

## Examples

  # one call → exit code + output
  rx run HOST -- systemctl is-active nginx

  # feed stdin and get the result together
  printf 'c\na\nb\n' | rx run HOST -- sort

  # working directory + environment without a shell wrapper
  rx run HOST --cwd /srv/app --env NODE_ENV=production -- ./build.sh

  # elevate: passwordless doas, no TTY (do NOT use su — it needs /dev/tty)
  rx run HOST -- doas apt-get -y update
  printf 'key=value\n' | rx run HOST -- doas tee /etc/app.conf

  # start now, block for the result later (no polling)
  ID=$(rx start HOST -- ./migrate.sh | jq -r .id)
  rx wait HOST $ID --timeout 120

  # long-lived: take a handle now, read incrementally later
  ID=$(rx start HOST -- journalctl -fu nginx | jq -r .id)
  rx stdout HOST $ID --offset 0

  # interactive REPL over persistent stdin
  ID=$(rx start HOST -- python3 | jq -r .id)
  rx write HOST $ID "print(6*7)"
  rx stdout HOST $ID
  rx close-stdin HOST $ID

  # large or binary input streams unbounded via the pipe path
  cat firmware.bin | rx start HOST -- doas tee /var/lib/app/firmware.bin

  # copy a file into place atomically, perms set before it becomes visible
  rx cp ./app.conf HOST:/etc/app/app.conf --mode 0640
